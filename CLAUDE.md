# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Build

The Julia package is a thin wrapper around a Fortran shared library. **Nothing works until the library is built:**

```bash
cd src/chides_fortran && make      # builds libchides.so and moves it to src/
make clean                         # removes *.o, *.a
```

`src/Chides.jl` resolves the library as `dirname(pathof(Chides))/libchides.so`, so the `.so` must live in `src/`. The build products (`*.o`, `src/libchides.so`) are untracked and not gitignored — don't commit them.

On macOS with Homebrew gfortran the link step fails with `ld: library not found for -lSystem`; the makefile has no SDK path. Link manually:

```bash
cd src/chides_fortran && make          # compiles the .o files, then fails at link
gfortran -shared -L"$(xcrun --show-sdk-path)/usr/lib" -o libchides.so polymul.o polyfuns.o Hermite.o
mv libchides.so ../
```

## Test

```bash
julia --startup-file=no --project=. -e 'using Pkg; Pkg.test(julia_args=["--startup-file=no"])'
cd test && julia runtests.jl        # runtests.jl does push!(LOAD_PATH,"../src/")
```

`--startup-file=no` is needed on this machine: `~/.julia/config/startup.jl` loads Revise, which fails to precompile in the test subprocess and aborts the run before any test executes.

Individual tests are plain functions returning `Bool` in `test/*.jl` (e.g. `test_hmap(m)`), included and asserted from `runtests.jl`. To run one, `include("test/test_hmap.jl")` after `using Chides` and call it directly.

## Examples

```bash
julia examples/transport_1d.jl
julia examples/transport_2d.jl
julia examples/performance_test_1d.jl    # @btime comparison of taylor_to_hermite variants
```

Examples depend on `Plots` (pyplot backend), `TaylorSeries`, and `BenchmarkTools`, none of which are in `Project.toml` — run them in an environment where those are installed, not in `--project`. Several write `.gif` animations next to the script.

## Docs

```bash
julia --project=docs -e 'using Pkg; Pkg.develop(PackageSpec(path=pwd())); Pkg.instantiate()'   # once
julia --startup-file=no --project=docs docs/make.jl
```

Deployment runs from `.github/workflows/Documentation.yml` and needs a `DOCUMENTER_KEY` secret; locally the build ends with "could not auto-detect the building environment. Skipping deployment", which is expected.

Two things will fail the build, both by design:
- **Doctests run on every build.** `jldoctest` blocks in `src/Chides.jl` are executed and compared verbatim, so changing a printed value breaks the build.
- **`checkdocs` is on.** Docstrings live in `@autodocs` on `docs/src/function-index.md`, so new ones appear automatically — but a docstring on a *non-exported* name that no block picks up will error with `[:missing_docs]`.

Use `@doc raw"""..."""` for docstrings containing LaTeX. A bare `raw"""..."""` docstring is **silently not attached** — the function stays undocumented with no warning, and only shows up as a missing `@ref` much later. `docs/src/workflow.md` is still a TBD stub.

## Architecture

CHIDES implements the **Hermite–Taylor method** for hyperbolic PDEs. Two ideas drive every file:

**1. Data is scaled Taylor coefficients, not point values.** A grid function `u` is stored as `h^k D^k u(x_i)/k!` for `k = 0..m`. So a 1D primal field is `up[1:m+1, 1:nx]`, a 2D one is `up[1:m+1, 1:m+1, 1:nx, 1:ny]` (mixed x/y derivatives, scaled by `hx^i * hy^j`). Initial data is generated by automatic differentiation with `TaylorSeries.jl` (`Taylor1` in 1D, `set_variables`/`getcoeff` in 2D), then rescaled by powers of `h`.

**2. Time stepping alternates primal ↔ dual grid in half steps.** Each half step is: interpolate cell-edge Taylor data to a degree-`2m+1` Hermite polynomial centered at the cell midpoint, then advance that polynomial by `dt/2` using a Cauchy–Kovalevskaya (Taylor-in-time) recursion. The dual grid has one extra point per dimension (`ud[1:m+1, 1:nx+1]`); two half steps return to the primal grid.

**The interpolation matrix `Hmat`** is the hinge between the two. `hermitemap!(Hmat, m, xl, xr, xc, icase)` `ccall`s Fortran `hermite_`, producing the `(2m+2)×(2m+2)` map from Taylor data at `xl` and `xr` to Taylor data at `xc`. Every solver builds it once on the reference cell (`-1, 1, 0, icase=0`) and reuses it, because the data scaling by `h^k` makes the map grid-independent. `icase` selects interior (`0`) vs. left/right boundary collocation.

**Exported Julia API** (`src/Chides.jl`) is deliberately small:
- `hermitemap!` — the Fortran call
- `taylor_to_hermite1d!` — apply `Hmat` to a pair of adjacent cells (hot loop; hand-unrolled with `@inbounds`)
- `primal2plot1d!` / `primal2plot2d!` — evaluate the interpolant on an `nref`-times refined grid for plotting; these are the only place the polynomial is evaluated pointwise

**Solver drivers live in `examples/`, not in the package.** This is the current state of the project: `Chides` supplies interpolation + plotting, each example supplies its own PDE update and grid sweep.
- `examples/chides_sim_1d_scalar.jl` — `module sim` with the `Chides_simulation_1D` mutable struct (grids, `Hmat`, work arrays, `q = 2m+4` time-Taylor order) plus `evolvep2d_1d_scalar!` / `evolved2p_1d_scalar!`, which handle the periodic wrap explicitly at the first/last cell.
- `examples/transport_2d_funs.jl` — `p2d_2d!` / `d2p_2d!`, plus `t2h_2d!` which does the 2D interpolation as two tensor-product passes of `Hmat` (all y-data to face midpoints, then all x-data to the cell center). `p2d_2d!` handles the four periodic edges and four corners as separate explicit blocks.
- `pdeupdate!` is redefined per example — it is the PDE-specific part. For transport it is the Taylor recursion `u^{(t+1)}_{idx} = (cfl/idt)(idx+1) u^{(t)}_{idx+1}`, summed with `dfact = 0.5^l` to land on the half step.
- `examples/oned_routines.jl` holds numbered variants (`taylor_to_hermite1d1!`..`4!`, `interpolate_to_dual1d1!`..`7!`) that exist only for `performance_test_1d.jl` benchmarking; variant `4` is the one promoted into `src/Chides.jl`.

**Fortran side** (`src/chides_fortran/`): `Hermite.f90` has the `Hermite` map plus `binomial` and `point_to_Taylor` (Björck–Pereyra on Chebyshev nodes). `polyfuns.f90` and `polymul.f90` implement truncated-Taylor arithmetic (`tpolymul`, `tpolydiv`, `tpolypow`, `tpolyexp`, `tpolyinv3`, `extrapolate`) for nonlinear PDEs — compiled into the library but **not yet wrapped from Julia**; wrapping them follows the `ccall((:name_, fortran_lib_str), ...)` pattern in `hermitemap!` (note the trailing underscore and `Ref{}` argument types).

`old_rst_stuff/` is documentation for the original Fortran-only CHIDES code (transport, Burgers, acoustics, Navier–Stokes). It describes methodology that this Julia port has not reimplemented, and is the best reference for the math.
